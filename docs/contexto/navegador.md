# Control del navegador

> Cuándo leerlo: abrir sitios, pestañas, navegación con chrome-devtools-mcp.

- **Control del navegador por voz**: "abre mi linkedin" → tool `open_in_browser` (browser) → `POST /browser/open` → el agente resuelve el alias (`SITE_ALIASES` en `apps/agent/src/browser.ts`: alias → dominio dicho tal cual → búsqueda de Google) y abre el Chrome REAL con `open -a` (sesiones iniciadas, visible). Verbos rápidos por AppleScript nativo de Chrome — sin CDP: `control_browser` (back/forward/reload/close_tab/next_tab/prev_tab/scroll_*), `switch_browser_tab` (match por título/URL) y `list_browser_tabs` sobre `GET /browser/tabs` · `POST /browser/tab` · `POST /browser/command` (allowlist semántica, respuestas 200 con `{ok,error}` para que la voz relate el error tal cual). OJO AppleScript: dentro del `tell "Google Chrome"` la constante `tab` queda sombreada por la CLASE tab (se concatena el literal "tab") — capturar `set sep to tab` FUERA del tell. El scroll usa `execute javascript` y exige activar una vez Ver → Desarrollador → "Permitir JavaScript de Apple Events" (el error ya lo dice hablado). **Navegación PROFUNDA en lenguaje natural** ("ve a la página de precios de X y dime cuánto cuesta"): tool de voz `browse_web` → `POST /browser/navigate` → tarea SDK (mismo motor `startTask`) con las tools de **`chrome-devtools-mcp`** (dep pinneada del agente, stdio con `--browserUrl` — flags en camelCase) sobre un **Chrome CDP dedicado** (perfil `~/.hermes-os/chrome-hermes`, puerto 9222, visible; Chrome 136+ bloquea CDP en el perfil personal, por eso la instancia aparte — Rulo inicia sesión en sus sitios UNA vez ahí y persiste). El MCP solo se CONECTA (nunca lanza Chrome): `ensureCdpChrome()` en browser.ts lo garantiza desde el `canUseTool` de session.ts (las tools `mcp__chrome-devtools__*` NO van en allowedTools a propósito, para pasar por ese hook). Flujo del agente: `navigate_page` → `take_snapshot` (uids) → `click`/`fill` → verificar con otro snapshot. `HERMES_BROWSER_AGENT=off` lo apaga.
