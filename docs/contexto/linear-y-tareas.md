# Linear y el tablero de tareas

> Cuándo leerlo: issues, copy prompt, ejecutar desde linear, triage de accionables.

- **Linear (manejo de tareas, híbrido)**: cliente GraphQL en `apps/agent/src/linear.ts` (`LINEAR_API_KEY` + `LINEAR_TEAM_KEY` opcional). Tools `create_linear_issue` / `list_linear_issues`: el agente junta contexto real (vault/knowledge/code-graph) y publica el issue con título imperativo, descripción con criterios de aceptación y un bloque **"Copy prompt"** al final (fence de código — Linear le pone botón de copiar) con el prompt autocontenido para ejecutar la tarea en Claude Code. Los proyectos de Linear son espejo 1:1 de los activos del vault (`resolveProjectId`: slug → nombre canónico → proyecto de Linear, se auto-crea); el param `project` de la tool mete el issue al proyecto correcto. Además, `session.ts` registra el **MCP oficial de Linear** (`https://mcp.linear.app/mcp`, misma key como Bearer — headless, sin OAuth) para el resto del catálogo: actualizar estados, comentar, buscar, ciclos. Crear issues va SIEMPRE por la tool custom (formato Copy prompt garantizado por código, instruido en system-prompt.ts).
- **Tab TAREAS = tablero Linear-first**: Linear es la verdad de las tareas; la tabla local `tasks` solo guarda filas-puente (`local_key = linear:RUL-x`, `linear-run.ts`) que enganchan cada issue al motor existente de runs/stream/ejecuciones. Rutas `/linear/board` (issues + overlay local) · `/linear/issue/:id` (detalle + `copyPrompt` extraído del fence) · `/execute` (puente → In Progress → run headless → comentario con métricas al terminar; Done lo decide el humano) · `/state` · `POST /linear/issues` (Hermes crea el issue con contexto, async). El triage de accionables de juntas es Linear-first (pendiente/ejecutar crean el issue PRIMERO; el exec_prompt del accionable es su Copy prompt; sin key cae al flujo local): la respuesta incluye `issue`, la fila-puente guarda meeting_id/idx y `overlayTaskState` (meetings/store.ts) saca `linear_identifier`/`linear_url` de la URL en `task.detail` → chip "RUL-x ↗" en MeetingDetail, cuyos botones son "▶ Ejecutar / ◫ Crear en Linear / ✕ Ignorar" + bulk "◫ Todos a Linear" (pendientes en lote); ejecutar desde la junta abre la consola con `openTaskRun` (composer atado a la tarea). UI: `LinearBoard` (lista agrupada por estado estilo Linear, chips de proyectos ACTIVOS) → clic = `LinearIssueView` CENTRAL (← volver, cuerpo + sidebar de propiedades + ejecuciones) → Ejecutar abre la CONSOLA principal (tab claude): `ClaudeTerminal` con ⏹ Detener + composer de chat (`onSend` rutea por `continueTask` cuando hay `ws.claudeTaskId` — memoria de ejecuciones — o `claudeStartRun` para sesiones sueltas). Ojo `vault/projects.ts`: la nota principal de una carpeta es la que se llama como la carpeta (ikigai/Ikigai.md), no la primera alfabética.
